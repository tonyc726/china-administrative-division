# 政区信息面板设计规格

> Date: 2026-07-18
> Author: Jiangfeng
> Status: 待评审
> Version: 0.2

## 一、项目背景

在现有的「中国行政区划时光机」地名档案卡片（`apps/web/src/components/ShareCard.tsx`）基础上，新增政区信息展示面板，包括：

- 百度百科摘要（县级及以上）
- 政区坐标（全级别，来自 dmfw 地名库 `stname/listPub` 接口）
- 高德地图跳转链接（全级别）
- 分级展示策略（省/市/县/乡/村）

## 二、设计目标

1. **合规优先**：严格控制版权风险。以「纯 MIT 干净分发」为不可妥协前提，第三方数据不得污染代码许可。
2. **分级适配**：不同行政级别展示对应粒度的信息。
3. **风格统一**：与现有设计系统一致，不引入 emoji，使用内联 SVG icon（与 `BrandMark.tsx`/`Scrubber.tsx` 既有风格一致，不引入 icon 库）。
4. **性能友好**：数据按需加载，不影响首屏性能，且与 SSG 预渲染规格（见第十三章）解耦。

## 三、法律风险防控（核心约束）

### 3.1 许可兼容性命题（首要问题）

项目代码采用 MIT 协议（`LICENSE`，Copyright 2026 tonyc726）。MIT 明确**授予下游商业使用与原样再分发权利**。但本面板引入的两类第三方数据，版权均不归项目所有：

| 数据 | 上游版权性质 | 与 MIT 的张力 |
|------|--------------|---------------|
| 百度百科摘要 | 商业 UGC 平台，受百度 ToS 约束 | MIT 不涵盖第三方版权内容；"合理引用"是抗辩理由而非权利 |
| dmfw 坐标 | 民政部「许可 + 署名 + 禁商业性原版原式转载」 | MIT 授予下游再分发/商业使用，超出上游授权范围（nemo dat quod non habet） |

> **修正 v1.0 的推理错误**：v1.0 曾以「MIT 开源」作为「项目非商业性质」的证据来抵御百科商业用途争议。这是错误的——MIT 恰恰是 permissive（授予商业使用），与「非商业」相反。项目的非商业属性来自**运营事实**，不来自协议；且若要强化「合理引用」抗辩，应在事实层面声明非商业运营，而非误引 MIT。

由此确立三条铁律：

1. **数据文件不纳入 MIT 授权范围**。`LICENSE` / `README` 单独声明：代码 MIT，第三方数据文件版权归属各自上游，项目仅在各自条款下使用，不授权下游再分发其原始内容。
2. **dmfw 坐标走「衍生数据集」论证**（沿用 2026-07-13 既定决策的 B 方案）：只取 `name` + 坐标，join 进项目自有 12 位 code 体系，**弃用**地名库 20 位 `place_code`，显著署名「中国·国家地名信息库」——论证为衍生数据集而非「原版原式转载」。并行（C 方案）经 `contact.html` 去函民政部确认可否用于开源再分发。
3. **百科摘要走「合理引用」边界**：150–200 字、显著署名、跳转原文、免责声明。项目以非商业运营为事实抗辩（非以 MIT 为证据）。

### 3.2 版权合规

| 风险点 | 防控措施 |
|--------|----------|
| 全文转载侵权 | **仅抓取摘要**，限制单条 150–200 字（合理引用范围） |
| 未标注来源 | 每条数据强制包含 `source`、`sourceUrl` 字段；前端显式标注「资料来源：百度百科」并带跳转链接 |
| 商业用途争议 | 在页面底部与 README 声明项目**事实非商业运营**（学习研究用途）；声明「百科内容归原作者所有，仅供参考」——不以 MIT 作为非商业证据 |
| 二次分发风险 | 百科/坐标数据文件独立打包，不与 GB2260 原始数据混合；README 单独说明第三方数据版权归属与代码 MIT 许可分离 |
| nemo dat 冲突 | dmfw 坐标采 B 方案衍生数据集论证 + C 方案去函确认；百科摘要不进 MIT 授权范围 |

### 3.3 抓取合规

```typescript
const CRAWL_CONFIG = {
  concurrency: 2,           // 并发不超过 2
  delayPerReq: 3000,       // 每请求间隔 3 秒
  userAgent: 'Mozilla/5.0 (compatible; ChinaDivisionBot/1.0; +https://github.com/tonyc726/china-administrative-division)',
  maxRetries: 2,
  timeout: 10000,
} as const;
```

**step 0（合规前置）**：抓取前必须检查并遵守目标站 `robots.txt`；百科抓取需额外评估百度 ToS，若禁止自动化访问则改用维基百科兜底或放弃该源。

### 3.4 免责机制

- **数据层面**：新增 `disclaimer` 字段，标注「本摘要为机器自动提取，可能过时或不准确，请以官方信息为准」
- **展示层面**：百科面板底部固定显示免责声明小字
- **法律层面**：`LICENSE` 增加「第三方数据免责条款」——声明数据文件版权归属上游、代码 MIT 不构成对第三方数据再分发的授权（注意：这是免责声明，非对 MIT 追加限制性条款，不破坏代码部分的纯 MIT）

### 3.5 红线（坚决不做）

- ❌ 不抓取百度百科全文
- ❌ 不存储百度百科的图片、多媒体资源
- ❌ 不抓取高德的地图瓦片数据
- ❌ 不伪造、编造百科内容
- ❌ 不把第三方数据原样（原版原式）打进 MIT 包再分发
- ❌ 不使用 dmfw 的 20 位 `place_code`（避免「原版原式转载」认定），只取 name + 坐标 join 进自有 12 位码

## 四、数据源选择

### 4.1 主数据源

| 数据源 | 覆盖范围 | 用途 | 现状备注 |
|--------|----------|------|----------|
| 百度百科 | 省/市/县 | 摘要、面积、人口 | ⚠️ **未在项目数据源评估文档（`docs/数据采集现状评估与提升路径.md`）中**，系本规格新增提案，需先与数据源评估对齐后再实施 |
| dmfw `stname/listPub` | 全级别 | 坐标（CGCS2000，无 GCJ-02 偏移） | ⚠️ **crawler 现用的 `xzqh/getList`（`packages/crawler/src/dmfw.ts:11`）不采集坐标**；带坐标的 `stname/listPub` 接口尚未实现，需新建抓取器（见第八章） |

### 4.2 备用数据源

- 维基百科（中文）：百度词条缺失或质量差时（注意：维基 CC BY-SA 3.0，署名即可，合规性优于百度）
- 民政部地名库：标准名称校验
- 省/市政府官网：最新政区信息

### 5.2 类型定义

```typescript
// packages/crawler/src/baike-types.ts

/** 政区百科摘要（省/市/县通用） */
export interface PlaceWiki {
  /** 项目 12 位扩展码（如县级 XXXXXX000000，与 shards/ 命名一致） */
  code: string;
  /** 标准名称 */
  name: string;
  /** 百科摘要（150-200 字，机器提取后人工截断） */
  summary: string;
  /** 面积（统一平方公里，infobox 解析后单位归一） */
  area?: number;
  /** 人口（统一万人，最新普查数据，单位归一） */
  population?: number;
  /** 所属地理区域：华东/华北/华南/华中/西南/西北/东北（由省级码前 2 位派生，非取自百科） */
  region?: string;
  /** 资料来源：baike.baidu.com / zh.wikipedia.org */
  source: string;
  /** 原始词条 URL */
  sourceUrl: string;
  /** 抓取时间戳 */
  fetchedAt: number;
  /** 数据质量分：0-5（人工标注，仅覆盖抽查样本，未抽查项为 null） */
  quality: number | null;
}
```

> **修正 v1.0**：① `code` 由「6 位」改为「12 位」，与项目分发体系（`stats.json`、`shards/` 均为 12 位）一致；② **移除 `coord` 字段**——坐标统一在 `coords/` 管理，避免县级坐标在 wiki/ 与 coords/ 双写（DRY）；③ `quality` 改为可空，诚实反映「仅抽查 10%」的事实，未抽查项不得填默认值。

```typescript
/** county.meta.json */
export interface WikiMeta {
  version: string;           // '2026.07'

  /** 项目 12 位扩展码 */
  code: string;
  /** 标准名称 */
  name: string;
  /** 经纬度坐标 [lon, lat]，CGCS2000 体系存储（≈WGS84，差异 <1m） */
  coord: [number, number];
  /** 地名库 placeTypeCode，用于口径过滤（见 5.3） */
  placeTypeCode: string;
  /** 来源标注（合规要求每条坐标带来源） */
  source: 'dmfw-stname';
}
```

### 5.3 坐标口径与坐标系（新增，规避已知陷阱）

**口径陷阱（27xxx 双重登记）**：地名库 `stname/listPub` 中，`21610`（行政村）与 `27610`（村民委员会）、`21620`（社区）与 `27620`（社区居委会）是**同一实体的双重登记**（21xxx=行政区域类，27xxx=单位法人类）。四者相加会算出 161% 的假覆盖率。**正确口径 = `21610` + `21620`，排除 `27610`/`27620`**。`CoordRow.placeTypeCode` 即为此过滤保留。

**坐标系归一**：
- **存储统一 CGCS2000**（地名库原生，≈WGS84，无 GCJ-02 偏移，直接可用）。
- **跳转高德时做 WGS84 → GCJ-02 转换**：高德 URI API 接收 GCJ-02，直接喂 CGCS2000 会在大陆偏移数十至数百米。转换在 `getAmapLink` 内完成（见 7.4）。
- **不采集百科 infobox 坐标**：避免与 dmfw 坐标混用造成坐标系混乱。

## 六、分级展示策略

| 级别 | 展示内容 | 数据源 |
|------|----------|--------|
| **省级** | 百科摘要 + 坐标 + 面积 + 人口 + 高德链接 + 百科链接 | 百度百科 |
| **市级** | 百科摘要 + 坐标 + 面积 + 人口 + 高德链接 + 百科链接 | 百度百科 |
| **县级** | 百科摘要 + 坐标 + 面积 + 人口 + 高德链接 + 百科链接 | 百度百科（主） |
| **乡级** | 所属县级百科（标注「所属区县概况」） + 乡级坐标 + 高德链接 | dmfw 坐标 + 父级百科 |
| **村级** | 仅坐标 + 高德链接 + 上级链路说明 | dmfw `stname/listPub` 坐标 |

> **父级解析**：乡级/村级定位「所属区县」须走项目自有 parent-chain（乡级 12 位码前 6 位不一定是其县级——市辖区下的街道，县级码是市辖区码），**不可用前缀截断**。

### 7.4 高德地图跳转

**合规推理**：高德对商业地图源有「三重禁止」（禁存储/禁衍生数据集/禁爬取分发，见 `packages/crawler/src/verify.ts:255-257`、`docs/数据采集现状评估与提升路径.md:72`）。本规格使用的高德 **URI API 仅生成一个跳转链接**，不存储高德数据、不构建衍生数据集、不爬取分发，故不触发三禁，合规且无需 API Key。

**坐标系转换**：存储为 CGCS2000/WGS84，跳转前须转 GCJ-02（高德 URI 接收 GCJ-02），否则定位偏移。

```typescript
/**
 * WGS84 -> GCJ-02 转换（简化版，大陆境内偏移修正）
 * 生成高德地图跳转链接（URI API，合规，无需 API Key）
 * 文档：https://lbs.amap.com/api/uri-api/summary
 */
function getAmapLink(name: string, coord: [number, number]): string {
  const [lon, lat] = coord;
  const [gcjLon, gcjLat] = wgs84ToGcj02(lon, lat);
  return `https://uri.amap.com/marker?position=${gcjLon},${gcjLat}&name=${encodeURIComponent(name)}`;
}
```

## 八、抓取流程设计

### 8.1 脚本位置


> **修正 v1.0**：① v1.0 称 build-coords「复用 dmfw 数据」——**crawler 现用的 `xzqh/getList` 无坐标**，坐标须由新建 `stname.ts` 采集 `stname/listPub`；② 运行入口遵循 `packages/crawler/src/run-*.ts` 既有模式，web 数据构建放 `apps/web/scripts/`（与 `build-data.ts` 一致，bun），不放根 `scripts/`（根 `scripts/` 是 shell + nbs 导出）。

### 8.2 百科抓取流水线

```
0. 检查并遵守 baike.baidu.com/robots.txt；评估 ToS，禁止则改维基兜底
   ↓
1. 读取省/市/县政区列表（34 + 333 + 2846 ≈ 3213 个，非仅县级）
   ↓
2. 批量搜索百度百科词条 ID
   ├── 精确匹配：「XX县」「XX区」「XX市」
   └── 歧义处理：带上级限定「宁波市慈溪市」
   ↓
3. 逐页抓取（并发 2，间隔 3s），缓存原始响应（便于逻辑重算、降低封 IP 风险）
   ├── 提取词条摘要第一段
   ├── 解析 infobox（面积、人口）+ 单位归一（面积→km²，人口→万人）
   └── 自动截断到 200 字内
   ↓
4. 质量检查
   ├── 摘要长度 < 50 字 -> 标记为低质量
   ├── 单位无法归一 -> area/population 留空，不臆造
   └── 政区内容敏感性：不做主动过滤（避免审查姿态），disclaimer 覆盖「内容可能存在争议或滞后」
   ↓
5. 生成 province.json / city.json / county.json + county.meta.json
   ↓
6. 人工抽样审核（抽查 10%，未抽查项 quality=null）
```

> **修正 v1.0**：① v1.0 step 4「无坐标从 dmfw 补全」删除——坐标统一由 `stname.ts` 采集，百科流程不混入坐标，避免坐标系混乱；② 补单位归一步骤（v1.0 把 area/population 当干净 number，忽略 infobox 单位混乱）；③ 补 robots step 0 与原始响应缓存。

### 8.3 坐标抓取

坐标数据由独立的 `stname/listPub` 抓取器采集，详细工程设计见 `2026-07-18-dmfw-stname-coords-design.md`。本规格仅摘要：接口为 POST、6 位码、size≤100、有非确定性抖动；须口径过滤（21610+21620，排除 27xxx 双登）与坐标系归一（CGCS2000 存储、跳转前 WGS84->GCJ-02）。全量耗时 ~1.5-2.5 小时（并发 2-3，含抖动重试），与百科抓取独立，不混入「2.7 小时」估算。

### 8.4 增量更新策略

- **百科**：按「词条最后编辑时间变化」触发重抓（编辑时间戳不可靠时，退化为低频全量校准）；**不**按 `quality < 3` 重抓——低质量常因词条本身内容薄，重抓无济于事。
- **坐标**：地名库无变更事件流，采用民政部令第 79 号「每年 1 月全量校准 + 日常不增量」节律。
- **首次全量**：百科 ~3213 × 3s ≈ **2.7 小时**（省+市+县，非仅县）；坐标独立另计。
