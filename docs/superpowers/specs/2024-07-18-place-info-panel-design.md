# 政区信息面板设计规格

> Date: 2024-07-18
> Author: Claude Code
> Status: Draft
> Version: 1.0

## 一、项目背景

在现有的「中国行政区划时光机」地名档案卡片基础上，新增政区信息展示面板，包括：
- 百度百科摘要（县级及以上）
- 政区坐标（全级别，来自 dmfw 地名库）
- 高德地图跳转链接（全级别）
- 分级展示策略（省/市/县/乡/村）

## 二、设计目标

1. **合规优先**：严格控制版权风险，合理引用、明确标注来源
2. **分级适配**：不同行政级别展示对应粒度的信息
3. **风格统一**：与现有设计系统一致，不引入 emoji，使用 SVG icon
4. **性能友好**：数据按需加载，不影响首屏性能

## 三、法律风险防控（核心约束）

### 3.1 版权合规

| 风险点 | 防控措施 |
|--------|----------|
| 全文转载侵权 | **仅抓取摘要**，限制单条 150-200 字（合理引用范围） |
| 未标注来源 | 每条数据强制包含 `source`、`sourceUrl` 字段；前端显式标注「资料来源：百度百科」并带跳转链接 |
| 商业用途争议 | 明确项目非商业性质（MIT 开源）；在页面底部添加「百科内容归原作者所有，仅供参考」 |
| 二次分发风险 | 数据文件独立打包，不与 GB2260 原始数据混合；README 单独说明百科数据的版权归属 |

### 3.2 抓取合规

```typescript
const CRAWL_CONFIG = {
  concurrency: 2,           // 并发不超过 2
  delayPerReq: 3000,       // 每请求间隔 3 秒
  userAgent: 'Mozilla/5.0 (compatible; ChinaDivisionBot/1.0; +https://github.com/tonyc726/china-administrative-division)',
  maxRetries: 2,
  timeout: 10000,
} as const;
```

### 3.3 免责机制

- **数据层面**：新增 `disclaimer` 字段，标注「本摘要为机器自动提取，可能过时或不准确，请以官方信息为准」
- **展示层面**：百科面板底部固定显示免责声明小字
- **法律层面**：在项目 LICENSE 文件中增加「第三方数据免责条款」

### 3.4 红线（坚决不做）

- ❌ 不抓取百度百科全文
- ❌ 不存储百度百科的图片、多媒体资源
- ❌ 不抓取高德的地图瓦片数据
- ❌ 不伪造、编造百科内容

## 四、数据源选择

### 4.1 主数据源

| 数据源 | 覆盖范围 | 用途 |
|--------|----------|------|
| 百度百科 | 省/市/县 | 摘要、面积、人口 |
| dmfw 地名库 | 全级别 | 坐标（CGCS2000） |

### 4.2 备用数据源

- 维基百科（中文）：百度词条缺失或质量差时
- 民政部地名库：标准名称校验
- 省/市政府官网：最新政区信息

## 五、数据结构设计

### 5.1 文件结构

```
apps/web/public/data/
├── wiki/
│   ├── county.json          # 县级百科摘要（主文件 ~5MB）
│   └── county.meta.json     # 元数据：抓取时间、版本、统计信息
├── coords/
│   ├── county.json          # 县级坐标（~2846 条）
│   ├── township.json        # 乡级坐标（~4 万条）
│   └── village.json         # 村级坐标（~62 万条）
└── ...（现有文件不变）
```

### 5.2 类型定义

```typescript
// packages/crawler/src/baike-types.ts

/** 县级百科摘要 */
export interface CountyWiki {
  /** 区划代码（6 位） */
  code: string;
  /** 标准名称 */
  name: string;
  /** 百科摘要（150-200 字，机器提取后人工截断） */
  summary: string;
  /** 经纬度坐标（CGCS2000/WGS84，来自民政部地名库） */
  coord?: [number, number];
  /** 面积（平方公里，来自 infobox） */
  area?: number;
  /** 人口（万人，最新普查数据） */
  population?: number;
  /** 所属地理区域：华东/华北/华南/华中/西南/西北/东北 */
  region?: string;
  /** 资料来源：baike.baidu.com / zh.wikipedia.org / mca.gov.cn */
  source: string;
  /** 原始词条 URL */
  sourceUrl: string;
  /** 抓取时间戳 */
  fetchedAt: number;
  /** 数据质量分：0-5（人工标注） */
  quality: number;
}

/** county.meta.json */
export interface WikiMeta {
  version: string;           // '2024.07'
  fetchedAt: number;         // 构建时间
  totalCount: number;        // 总条目数
  coverage: number;          // 覆盖率 %
  sources: Record<string, number>;  // 各来源统计
  disclaimer: string;        // 免责声明文本
}

/** 坐标数据（全级别，扁平数组） */
export interface CoordRow {
  code: string;
  name: string;
  coord: [number, number];
}
```

## 六、分级展示策略

| 级别 | 展示内容 | 数据源 |
|------|----------|--------|
| **省级** | 百科摘要 + 坐标 + 面积 + 人口 + 高德链接 + 百科链接 | 百度百科 |
| **市级** | 百科摘要 + 坐标 + 面积 + 人口 + 高德链接 + 百科链接 | 百度百科 |
| **县级** | 百科摘要 + 坐标 + 面积 + 人口 + 高德链接 + 百科链接 | 百度百科（主） |
| **乡级** | 所属县级百科（标注「所属区县概况」） + 乡级坐标 + 高德链接 | dmfw 坐标 + 父级百科 |
| **村级** | 仅坐标 + 高德链接 + 上级链路说明 | dmfw 地名库坐标 |

### 7.3 Icon 设计规范

- 尺寸：14×14 或 16×16
- 线条粗细：1.2px
- 颜色：默认 `#57534a`（ink-soft），高亮 `#bc5738`（clay）
- 风格：线性图标，圆角线帽，与现有风格统一

### 7.4 高德地图跳转

使用高德地图官方 URI API（合规，无需 API Key）：

```typescript
/**
 * 生成高德地图跳转链接
 * 文档：https://lbs.amap.com/api/uri-api/summary
 */
function getAmapLink(name: string, coord: [number, number]): string {
  const [lon, lat] = coord;
  return `https://uri.amap.com/marker?position=${lon},${lat}&name=${encodeURIComponent(name)}`;
}
```

### 7.5 降级策略

无百科数据时显示：


无坐标数据时，地图链接隐藏。

## 八、抓取流程设计

### 8.1 脚本位置

```
packages/crawler/src/baike.ts          # 百度百科抓取器
packages/crawler/src/baike-types.ts    # 类型定义
scripts/build-baike.ts                  # 百科构建入口脚本
scripts/build-coords.ts                 # 坐标构建入口脚本（复用 dmfw 数据）
```

### 8.2 百科抓取流水线

```
1. 读取县级政区列表（2846 个）
   ↓
2. 批量搜索百度百科词条 ID
   ├── 精确匹配：「XX县」「XX区」「XX市」
   └── 歧义处理：带上级限定「宁波市慈溪市」
   ↓
3. 逐页抓取（并发 2，间隔 3s）
   ├── 提取词条摘要第一段
   ├── 解析 infobox（面积、人口、坐标）
   └── 自动截断到 200 字内
   ↓
4. 质量检查
   ├── 摘要长度 < 50 字 → 标记为低质量
   ├── 无坐标 → 从 dmfw 地名库补全
   └── 敏感词过滤（可选）
   ↓
5. 生成 county.json + county.meta.json
   ↓
6. 人工抽样审核（抽查 10% 条目）
```

### 8.3 增量更新策略

- 首次全量抓取：约 2846 × 3s ≈ **2.5 小时**
- 后续更新：每月运行一次，仅更新 `quality < 3` 的条目
- 变更检测：比对词条最后编辑时间，有变化才重抓

## 九、性能与数据量评估

| 指标 | 数值 | 影响 |
|------|------|------|
| county.json | ~4-5 MB | 首屏不加载，按需 fetch |
| county.meta.json | ~1 KB | 可忽略 |
| 坐标数据 | ~10 MB | 分片加载，按需请求 |
| 首屏加载影响 | 0 | 懒加载，用户展开面板才请求 |
| 构建时间 | ~2.5 小时 | CI 可夜间运行，不阻塞日常开发 |
| 存储增量 | ~15 MB | 现有 59 MB → 74 MB，可接受 |

## 十一、风险清单与应对

| 风险 | 概率 | 影响 | 应对措施 |
|------|------|------|----------|
| 百度反爬封 IP | 中 | 抓取中断 | 增加代理池支持；拆分成多天跑完 |
| 词条匹配错误 | 低 | 张冠李戴 | 增加人工审核抽样；匹配时带上级限定 |
| 摘要过时 | 低 | 信息不准 | 元数据标注抓取时间；每月增量更新 |
| 版权投诉 | 极低 | 法律风险 | 严格控制摘要长度；明确标注来源和免责；提供删除渠道 |
| 坐标数据缺失 | 中 | 地图不可用 | dmfw 村级覆盖率 97.9%，缺失项留空 |

## 十二、验收标准

- [ ] 省/市/县三级均能正确显示百科摘要
- [ ] 乡级/村级能正确复用所属县的百科并标注「所属区县概况」
- [ ] 所有级别有坐标时能跳转到高德地图对应位置
- [ ] 界面风格与现有设计系统一致，无 emoji
- [ ] 所有百科数据明确标注来源和免责声明
- [ ] 数据按需加载，不影响首屏性能
- [ ] 无坐标、无百科数据时优雅降级
