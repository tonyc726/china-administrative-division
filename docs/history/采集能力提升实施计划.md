## P0 · 最高性价比（先做）

### T1.1 — `maxLevel=2` 步长优化 ✅ 已完成（commit `c7b16e8`）

> **执行结果**：三样本离线确定性对比**全 0 差异**（宁夏 270 / 北京 359 / 海南 230 条逐条一致，验证直辖市跳级与省直管县）。全国全量请求 **2898→461（-84%）**，failures=0，21s。
> **语义纠正**：dmfw `maxLevel` 按**绝对 level 截断**而非树深度，入队判据改为「返回 children 为空且 level<maxLevel = 截断前沿」以正确覆盖跳级。
> **预估修正**：单省收益有限（宁夏 28→23），大头来自全国根 `''`（~2800 县作为孙节点被市级抓取带回）；原文「宁夏 26→6」为树深度模型误估。缓存 key 带 maxLevel 隔离；crawl-all 新增 6 单测全绿。

**目标**：把逐层 BFS（步长 1）改为步长 2，单次 `getList` 抓两层，全国全量请求从 ~3200 降至 ~342。

**改动文件**：
- `packages/crawler/src/dmfw.ts`：`fetchChildren` 增加 `maxLevel` 参数（默认 1，保持向后兼容）；或新增 `fetchSubtree(code, maxLevel)` 返回带嵌套 `children` 的节点树。
- `packages/crawler/src/crawl-all.ts`：`crawlAll` 的 BFS 循环步长改 2，展平两层、正确计算下一波 frontier。
- `packages/crawler/src/cache.ts`：缓存 key 需带 `maxLevel`（`get(code)`→`get(code, maxLevel)`），避免与旧 maxLevel=1 缓存串味。

**实现要点（FMEA）**：
1. **直辖市跳级**：北京 L1 直接挂 L3 区（无 L2）。步长 2 从 root 抓得到 `省(L1)+市(L2)`，但直辖市在 root 波直接给出 L3 区。下一波 frontier 必须是"已抓到、但其子尚未抓"的**每个节点的最深层**，不能假设固定层级。稳妥算法：抓 `code` (maxLevel=2) 得子(d+1)与孙(d+2)，**孙节点入下一波 frontier**（其子 d+3 未抓）；子节点不入队（其子=孙已抓）。对跳级节点按实际返回 level 判断，而非按理论深度。
2. **去重**：同一节点不得被两波重复抓取。用 `Set<string>` 记录"已作为抓取根请求过的 code"。
3. **叶子判定**：`node.level >= maxLevel(目标4)` 的节点不入 frontier。
4. **失败容错**：保持现有 `failures[]` 逐 code 记录、可重跑续爬语义不变。
5. **缓存兼容**：清空或隔离 `.cache/crawler-*`（旧缓存是 maxLevel=1 的单层结果，与新逻辑不兼容）。

**验收标准**（缺一不可）：
- [ ] 单省宁夏 `--root=640000000000` 跑通，产出的 `Division[]` 与旧 `maxLevel=1` 全量结果**逐条 code/name/level/parent_code 完全一致**（写对比脚本 diff 两次输出）。
- [ ] 实际网络请求数 `fetched` 显著下降（宁夏：旧 ≈ 1+5市+~20县 ≈ 26 → 新 ≈ 1+5 = 6，降幅可见）。
- [ ] 全国跑一次，总条数与上次全国跑通的 2446 条量级一致（记录于 memory `crawler-dmfw-nbs-level-mismatch`），失败节点可续爬。
- [ ] `pnpm --filter @cndiv/crawler test` 全绿；新增 crawl-all 步长2 的单测（用 fixture mock `fetchSubtree`）。
- [ ] 差分产出的 patch ops 数与旧版一致（证明数据无遗漏/无重复）。

**风险**：直辖市/省直管跳级处理错误 → 漏抓或重复。缓解：宁夏（有跳级）+ 北京（直辖市跳级）+ 海南（省直管县）三个样本必须都验收通过再上全国。

### T1.2 — 接入 xzqh 权威变更事件流，驱动增量 ✅ 已完成（commit `0947799` + 集成 `bb1f126`）

> **执行结果**：探清 `dcpid`=4 位年份本身、变更条目在 `div.tz_con` 内以 `<p>` 组织（标题/描述/括号落款）、全站 GBK。联网端到端 `cndiv-xzqh --year=2026` 正确解析「设立岑岭县 2026-03-26」「设立县级草湖市 2026-04-17」中文无乱码，新设实体正确落 `unresolved`（不臆造码）。
> GBK 解码单测 + 3 个真实 GB18030 fixture、extractPatch 集成（撤销+命中 resolver 产出合法 remove 过 validatePatch）、2022 空发布不报错，全绿。
> **集成**：index.ts 导出 xzqh、package.json 加 `cndiv-xzqh` bin + `test` 脚本；额外接入 `@cndiv/extractor` 跨包依赖 + tsconfig project reference（run-xzqh 必需）。

**目标**：抓 `xzqh.mca.gov.cn/description?dcpid=<年>` 的《县级以上行政区划变更情况》→ 逐条喂现有 `@cndiv/extractor.extractPatch` → 产出结构化 Patch，替代/补充 dmfw 全量差分（避开层级口径伪变更噪声，见 memory `crawler-dmfw-nbs-level-mismatch`）。

**改动文件**：
- 新增 `packages/crawler/src/xzqh.ts`：抓取 + GBK 解码 + cheerio 解析变更条目。
- 新增 `packages/crawler/src/run-xzqh.ts`：CLI `cndiv-xzqh`，落变更条目文本 → 调 extractor。
- `packages/crawler/package.json`：加 bin `cndiv-xzqh`；加依赖 `iconv-lite`（GBK 解码，`cheerio` 已在依赖内）。
- `packages/crawler/src/index.ts`：导出 xzqh API。

**实现要点（FMEA）**：
1. **dcpid 映射**：先探明 `dcpid` 参数与年份的对应关系（索引页 `dcpid=1` 列出全年份链接）。写一个 `listYearLinks()` 先抓索引解析出 `年份→dcpid` 映射，不硬编码。
2. **GBK 编码**：页面为 GB18030。用 `got(...).buffer()` 取字节 → `iconv-lite.decode(buf, 'gb18030')` → cheerio。**不可**直接 `.text()`（会乱码）。
3. **"无发布≠零变更"**：2022 年无条目是"县级调整冻结期"，解析空结果时记为"该年无发布"而非报错。
4. **回溯边界**：平台仅回溯到 1999，GB2260 1980–1998 区段无此源，文档标注。
5. **喂 extractor**：每条变更文本 → `extractPatch(text, { resolve })`，`resolve` 基于注水后 cache.db 名称索引（见 `@cndiv/reader`）。unresolved 落人工，不臆造码。
6. **产物守门**：extractor 产出经 `validatePatch` 才写入 `patches/`（与现有 dmfw 流程一致）。

**验收标准**：
- [ ] `listYearLinks()` 正确解析出 1999–2026 的 `年份→dcpid` 映射（抽查 2024/2025/2026 三年链接可访问）。
- [ ] 抓 2026 年页面，正确解析出已知条目"设立岑岭县(2026-03-26)""设立县级草湖市(2026-04-17)"，中文无乱码。
- [ ] 至少一条变更文本经 `extractPatch` 产出合法 Operation（过 `validatePatch`）；无法解析的落 `unresolved` 且打印。
- [ ] GBK 解码单测（fixture 存一段 GB18030 字节，断言解码后中文正确）。
- [ ] `cndiv-xzqh --year=2026` 端到端跑通，产出 patch 或明确的 unresolved 报告。

**风险**：xzqh 页面结构无 API 契约、可能改版。缓解：解析器对缺列/空表容错，纳入 T3.2 契约 smoke test。
