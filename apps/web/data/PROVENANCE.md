# china-bounds.json —— 出处、许可与**发布阻塞项**

> ⚠️ **这份数据现在不能随站公开发布。** 见下面「发布阻塞项」。效果先做出来了，风险显式挂在这里，
> 由人来决定是替换数据源、还是去送审。不要因为「它已经在仓库里了」就当作已经合规。

## 它是什么

34 个省级行政区的外轮廓 + **10 段南海断续线（九段线）**，经 Douglas–Peucker 简化后的紧凑格式：

```jsonc
{
  "provs": [{ "c": "13", "n": "河北", "r": [[lon, lat, lon, lat, …], …] }], // r = 外环，开环存储，闭合由渲染端负责
  "jd":    [[lon, lat, …], …]                                              // 十段线，未简化
}
```

4570 个点 / 66 KB 原始 / **21.8 KB gzip**。生成脚本：`simplify.ts`（`bun run simplify.ts 0.055 0.03`，需先把上游 GeoJSON 存为 `cn.json`）。

## 出处

- 上游：`https://geo.datav.aliyun.com/areas_v3/bound/100000_full.json`（阿里云 DataV.GeoAtlas）
- 取数日期：2026-07-14
- 上游的上游：**高德开放平台**。DataV 官方说明该数据「仅供学习交流使用」，版权问题需到高德开放平台确认。

## 发布阻塞项（两条，独立成立，缺一不可）

1. **数据许可**：DataV 的边界衍生自高德，声明仅供学习交流、不得商用。这与本项目自己的结论直接冲突 ——
   `packages/crawler/src/verify.ts` 的 `verifyCross` 是**故意留空的桩**，注释写明商业地图源 ToS 三重禁止
   存储 / 建库 / 再分发。采集侧严防死守的东西，不该从展示侧引回来。

2. **审图号**：在国内公网发布中国地图需经审核（《地图管理条例》）。**用第三方 GeoJSON 自己画的图，
   不会自动获得审图号。** 上游数据没有审图号，我们也没有。

   唯一不用自己送审的合法路径是：使用自然资源部【标准地图服务】(bzdt.ch.mnr.gov.cn) 下载的、
   **不修改几何**的标准地图。

## 已核对的事实

- 34 个省级要素齐全（含台湾省、香港、澳门），无空要素。
- **十段线 10 段完整**。简化过程曾经把它砍掉 4 段 —— 现在代码里对 `jd` 显式跳过简化、也不做面积过滤。
  这是国界，不是装饰；任何人改 `simplify.ts` 都必须保证这一条仍然成立。
- 容差随要素尺度缩放（`min(EPS, √area/30)`），否则澳门这类小要素会被 5km 容差整个抹平。

## 渲染端如何解耦

`apps/web/src/components/Hero.tsx` 只消费上面那个 `{provs, jd}` 契约，不关心它从哪来。
换数据源 = 换这一个文件，渲染代码一行不用动。
